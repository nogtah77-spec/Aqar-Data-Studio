قواعد إضافية إلزامية

1. استخدم فقط التقنيات والخدمات المجانية أو مفتوحة المصدر. لا تعتمد على أي خدمة مدفوعة لتشغيل النظام الأساسي، واجعل المشروع قابلاً للعمل بالكامل باستخدام الأدوات المجانية.

2. أنشئ ملف README.md احترافي يشرح المشروع، وبنيته، وطريقة التشغيل، وطريقة النشر، وطريقة ربط Supabase، وأي إعدادات يحتاجها أي مطور مستقبلاً.

3. أنشئ اختبارات أساسية (Basic Tests) للأجزاء المهمة لضمان استقرار المشروع، دون المبالغة في عددها أو تعقيدها.

4. أنشئ ملف CHANGELOG.md، وقم بتحديثه بعد كل مرحلة رئيسية أو أي Commit مهم، بحيث يتم توثيق جميع التغييرات بشكل منظم.

5. لا تقم بإنشاء أي بيانات تجريبية أو عقارات وهمية أو حسابات افتراضية أو محتوى تجريبي إلا إذا طلبت ذلك منك صراحة.

6. قم بإنشاء مجلد /docs داخل المشروع، وضع فيه جميع الوثائق الفنية للمشروع مثل:
PROJECT_VISION.md

واجعل هذه الملفات تُحدَّث مع تطور المشروع حتى تصبح المرجع الرسمي لأي مطور أو أي AI يعمل على المشروع مستقبلاً.

Git Workflow (Mandatory)

GitHub هو المصدر الرسمي والوحيد للمشروع.

بعد الانتهاء من كل مرحلة مستقرة أو أي ميزة رئيسية:

1. قم بعمل Git Commit برسالة واضحة تصف ما تم إنجازه.
2. ثم قم مباشرة بعمل Git Push إلى مستودع GitHub المرتبط بالمشروع.
3. لا تؤجل الـ Push حتى نهاية المشروع.
4. لا تترك أي عمل غير محفوظ على GitHub.
5. اعتبر GitHub هو النسخة الأساسية للمشروع وليس Replit.
6. إذا توقف العمل أو انتهى AI Limit في أي وقت، يجب أن يكون آخر تقدم موجود بالفعل على GitHub بحيث يمكنني فتح المشروع من أي حساب Replit جديد ومتابعة العمل من آخر Commit بدون فقدان أي شيء.
7. إذا احتجت أي صلاحية أو Authentication تخص GitHub فأخبرني فورًا.
